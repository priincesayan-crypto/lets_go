PLAN D'ACTION LET'S GO

Nous allons maintenant passer de l'idée → spécification → prototype → application testée.

PHASE 1 — Design de Let’s Go

➡️ C'est maintenant.

Avant de demander à Gemini d'écrire du code, on verrouille :

identité visuelle ;
écran d'accueil ;
fiche personne ;
écran d'ajout ;
écran d'import ;
recherche ;
boutons ;
navigation ;
animations ;
mode sombre ;
états vides/erreurs.

Objectif : Gemini ne doit pas avoir à inventer l'UX.

PHASE 2 — Architecture technique

Ensuite je vais te préparer la spécification exacte :

Let’s Go
│
├── UI
│   └── Jetpack Compose
│
├── Presentation
│   └── ViewModels
│
├── Data
│   └── Room
│
├── Import
│   └── Android Contacts Provider
│
├── Navigation
│   └── Jetpack Navigation
│
└── Android Intents
    ├── Téléphone
    └── Maps

Room est justement conçu comme une couche d'abstraction robuste au-dessus de SQLite.

Tu installeras :

Android Studio dernière version stable

Puis nous créerons :

Nom : Let's Go
Package : à définir

UI : Jetpack Compose

Gemini sera activé directement dans Android Studio.

PHASE 4 — Première version visuelle

Gemini aura une première mission extrêmement limitée :

Créer uniquement l'interface de Let’s Go.

Pas encore :

contacts ;
import ;

On veut d'abord pouvoir lancer l'application et dire :

« Oui, c'est exactement l'interface que je veux. »

PHASE 10 — Tests réels

On installera Let’s Go sur ton téléphone Android réel.

On testera :

Petite base

10 contacts.

Base normale

100–500 contacts.

Gros carnet

1 000+ contacts.

Cas extrême

Plusieurs milliers.

Et surtout :

Import sélectif de 5 contacts dans un carnet de plusieurs milliers.

C'est exactement là qu'on vérifiera que notre architecture respecte ton exigence de ne pas charger inutilement tout le carnet.
